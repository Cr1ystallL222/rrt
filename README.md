# 🛠 Remote Support & Administration Architecture (PoC)

Комплексное решение для легитимной технической поддержки и удаленного мониторинга рабочих станций под управлением Windows / Linux / macOS с управлением через Telegram-бота.

---

## 🏛 1. Архитектура системы

```
+--------------------------+                 +-------------------------------+
|  Целевой компьютер (ПК)  |                 |     Сервер (VPS / Cloud)      |
|  [client/client.py .exe] |                 |   [FastAPI / aiohttp + WSS]   |
|                          |   WebSocket     |                               |
|  - Авто-подключение      |<===============>|  - Менеджер активных сессий   |
|  - Heartbeat (пульс)     |  (JSON over WS) |  - Маршрутизация команд       |
|  - Захват экрана (mss)   |                 |  - Авторизация клиентов/токенов|
|  - Метрики CPU/RAM/Disk  |                 +---------------+---------------+
+--------------------------+                                 |
                                                             | aiogram 3.x
                                                             | (Polling / Webhook)
                                                             v
                                             +-------------------------------+
                                             |  Telegram Control Panel (Bot) |
                                             |  - Whitelist Admin IDs        |
                                             |  - Динамическое Inline-меню   |
                                             |  - Получение скриншотов/инфо  |
                                             +-------------------------------+
```

### Преимущества архитектуры на WebSocket (WSS):
1. **Преодоление NAT и файрволов:** Клиент сам инициирует исходящее соединение на сервер (порт 80/443), поэтому ему не требуется внешний "белый" IP-адрес или проброс портов.
2. **Мгновенная реакция (Real-time):** В отличие от медленного HTTP-опроса (polling), WebSocket позволяет администратору получать скриншоты и статус за доли секунды.
3. **Безопасность (End-to-End Auth):**
   - Клиент обязан передавать секретный токен `AUTH_TOKEN` при рукопожатии.
   - Telegram-бот фильтрует все входящие запросы через `ADMIN_IDS` — посторонние пользователи получают отказ в доступе.

## 🚀 2. Быстрый старт

### Шаг 1. Установка зависимостей
```bash
pip install -r requirements.txt
```

### Шаг 2. Настройка сервера
Отредактируйте `server/config.py` (или передайте через переменные окружения):
- `BOT_TOKEN`: токен вашего бота от `@BotFather`
- `ADMIN_IDS`: ваш Telegram user ID (можно узнать через `@userinfobot`)
- `CLIENT_AUTH_TOKEN`: произвольная секретная строка для авторизации клиентов

Запустите сервер:
```bash
python -m server.main
```

### Шаг 3. Настройка и запуск клиента
Отредактируйте `client/config.py`:
- `SERVER_URL`: адрес вашего сервера (например, `ws://YOUR_SERVER_IP:8765/ws`)
- `AUTH_TOKEN`: должен совпадать с `CLIENT_AUTH_TOKEN` на сервере

Запустите клиент для проверки:
```bash
python -m client.client
```

## 📦 3. Сборка в автономный .EXE файл (PyInstaller)

Для запуска на целевых компьютерах без Python выполните:

```bash
pyinstaller --onefile --noconsole --name "RemoteSupportAgent" --clean client/client.py
```

* **Параметры:**
  * `--onefile` — упаковывает интерпретатор Python, все зависимости (mss, PIL, websockets) в один переносимый исполняемый файл.
  * `--noconsole` (или `-w`) — скрывает черное окно консоли Windows при работе.
  * `--icon="icon.ico"` *(опционально)* — задает иконку для файла приложения.

Готовый файл появится в папке `dist\RemoteSupportAgent.exe`.
